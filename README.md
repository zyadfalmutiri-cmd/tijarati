# تجارتي (Tijarati) — منصة تحليلات الأعمال المجانية بالكامل

منصة أعمال ذكاء تجاري (Business Intelligence) توحّد متاجرك، فروعك، أنظمة نقاط
البيع، وبوابات الدفع في لوحة تحكم واحدة — **مجانية بالكامل**، بدون اشتراكات
أو إعلانات أو أي شكل من أشكال الترويج التجاري.

## المكدس التقني

- **Next.js 14** (App Router) + **React 18** + **TypeScript**
- **Tailwind CSS** + **shadcn/ui** (مكونات مبنية يدويًا فوق Radix Primitives)
- **TanStack Query** لإدارة حالة البيانات والتخزين المؤقت
- **Recharts** للرسوم البيانية التفاعلية
- **Framer Motion** للحركات والانتقالات
- **Supabase / PostgreSQL** (اختياري — التطبيق يعمل بوضع تجريبي كامل بدون أي إعداد)
- **Zustand** لحالة الاتصال بالتكاملات (مع الحفظ في localStorage)

## التشغيل محليًا

> ملاحظة: تم إنشاء هذا المشروع في بيئة بدون اتصال بالإنترنت، لذا لم يتم
> تنفيذ `npm install` أو `npm run build` هنا. اتبع الخطوات التالية على جهازك:

```bash
npm install
cp .env.example .env.local
npm run dev
```

التطبيق سيعمل مباشرة على `http://localhost:3000` **بدون أي إعداد إضافي** —
جميع البيانات (المبيعات، الفروع، المخزون، الموظفون...) مولّدة عبر طبقة
Mock Data حتمية (`src/lib/mock-data/generators.ts`) بحيث تكون تجربة الاستخدام
كاملة وواقعية من أول لحظة.

## الانتقال إلى بيانات حقيقية (Supabase)

1. أنشئ مشروع Supabase جديد.
2. نفّذ `supabase/schema.sql` في محرر SQL الخاص بالمشروع (يتضمن كل الجداول
   وسياسات Row Level Security).
3. أضف `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY` في
   `.env.local`.
4. استبدل الاستدعاءات داخل `src/hooks/*` من دوال `mock-data` إلى استعلامات
   Supabase الفعلية — الواجهات (الأنواع في `src/lib/types/domain.ts`) مطابقة
   تمامًا لمخطط قاعدة البيانات حتى لا تحتاج لتغيير أي مكوّن واجهة.

## البنية المعمارية

```
src/
  app/(dashboard)/        صفحات التطبيق (لوحة تحكم، فروع، تحليلات...)
  app/api/                مسارات API (المساعد الذكي، ربط ومزامنة التكاملات)
  components/ui/           مكوّنات shadcn/ui الأساسية القابلة لإعادة الاستخدام
  components/<feature>/    مكوّنات كل قسم (dashboard, branches, inventory...)
  hooks/                   طبقة TanStack Query — تُخفي مصدر البيانات (mock أو Supabase)
  lib/mock-data/           مولّد بيانات تجريبية حتمي وواقعي
  lib/integrations/        محرك التكاملات المعياري (انظر أدناه)
  lib/ai/                  محرك تحليل الأعمال الذي يشغّل المساعد الذكي
  lib/export/               تصدير CSV / Excel / PDF
  store/                    حالة Zustand لاتصالات التكاملات
supabase/schema.sql        مخطط قاعدة البيانات الكامل + RLS
```

## مركز التكاملات — البنية المعيارية

كل تكامل خارجي يُمثَّل بـ:

1. **`ConnectorDefinition`** — بيانات وصفية ثابتة (الاسم، الفئة، طريقة
   المصادقة) مسجّلة في `src/lib/integrations/core/registry.ts`. يحتوي الآن
   على **جميع** الخدمات المطلوبة (تجارة إلكترونية، نقاط بيع، دفع، محاسبة،
   بنوك، شحن، تسويق، استيراد بيانات).
2. **`ConnectorAdapter`** — منطق التشغيل الفعلي (الاتصال، المزامنة، الفصل)
   حسب الواجهة الموحّدة في `core/types.ts`. توجد خمسة تطبيقات مرجعية كاملة:
   - `adapters/shopify` (OAuth2)
   - `adapters/stripe` (مفتاح API)
   - `adapters/quickbooks` (OAuth2)
   - `adapters/square` (مفتاح API / نقاط بيع)
   - `adapters/woocommerce` (مفتاح API)

   باقي الخدمات (~45 خدمة) مسجّلة بالكامل في السوق (Marketplace) وقابلة
   للاتصال فورًا في الوضع التجريبي عبر محوّل عام (`GenericAdapter`)، وتصبح
   حقيقية بمجرد إضافة ملف محوّل جديد بنفس النمط — **دون أي تعديل على نواة
   التطبيق**.
3. **مسارات API** في `app/api/integrations/[connector]/{connect,callback,sync}`
   تُستدعى من واجهة السوق وتُفوّض العمل إلى المحوّل المناسب عبر
   `getAdapter(connectorId)`.

## المساعد الذكي

محرك تحليل قائم على قواعد استدلالية (`src/lib/ai/assistant.ts`) يقرأ نفس
البيانات المعروضة في اللوحة الرئيسية (لا أرقام وهمية) للإجابة عن: أسباب تغيّر
المبيعات، أفضل فرع أداءً، أعلى المنتجات ربحية، توقع مبيعات الشهر القادم،
واقتراحات تحسين الربح. يمكن ربطه اختياريًا بـ Claude عبر `ANTHROPIC_API_KEY`
لإعادة صياغة الإجابات بأسلوب أكثر حوارية دون تغيير الأرقام الفعلية (انظر
التعليق داخل `app/api/ai/assistant/route.ts`).

## ملاحظات مهمة

- **لا اشتراكات ولا مدفوعات ولا إعلانات** في أي مكان من الكود — هذا قرار
  معماري متعمّد وليس مجرد إعداد قابل للتفعيل لاحقًا.
- تصدير PDF يستخدم الخط الافتراضي في jsPDF الذي لا يدعم رسم حروف عربية
  بصريًا بشكل مثالي؛ لتجربة PDF عربية كاملة أضف خطًا عربيًا embedded (مثل
  Cairo أو Amiri) عبر `doc.addFont()`. تصدير CSV و Excel يدعمان العربية
  بشكل كامل وصحيح فورًا.
- الخريطة في صفحة الفروع مبنية بمكوّن SVG خفيف مصمم داخليًا (لا يتطلب مفتاح
  Google Maps API)؛ يمكن استبدالها لاحقًا بـ Mapbox/Google Maps بسهولة.
